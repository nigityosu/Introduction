# プログラミング入門サイト 仕様書

## 1. この文書について

この文書では、サイトの目的、学習体験、画面構成、実装方針を定めます。未決定の内容は「今後決めること」にまとめ、実装済みの機能と今後の構想を区別します。

## 2. サイトの目的

- プログラミング初心者が、プログラミングの楽しさと基本的な考え方を学べるようにする。
- パズルからコード編集へ段階的に進み、コードを書く前に処理や画面の構造を考える力を身につけてもらう。
- 学校説明会や部活動体験入部などで、学習や活動を紹介する場にも活用する。
- まずは費用を抑えて公開できる形を目指す。

## 3. 対象と基本方針

対象は、プログラミングをこれから学ぶ人です。専門用語には短い説明を添え、課題は小さな成功を積み重ねられる単位にします。

学習は「初級」「中級」「上級」の3段階で構成します。上級の最後に卒業試験を設けます。初級から上級へ進むには各段階の試験に合格する設計とします。

## 4. 学習体験

### 初級: パズルで構造を知る

コードを書く前に、画面の要素や動きの順序をブロックで組み立てます。課題の完成例や短い説明を示し、要素同士の関係を理解できるようにします。

初級試験は、学習した構造をヒントなしで組み立てる形式を基本とします。合格基準は、課題の採点方法とあわせて別途確定します。

### 中級: 言語の部品を使う

HTML、CSS、JavaScript などの実際の要素や命令をパズルの部品として扱います。部品には役割と使い方の説明を付けます。

通常課題では説明やヒントを使いながら制作し、試験では仕様に書かれた要望を満たすことを目指します。試験の問題数、制限時間、合格点は課題データとともに定義します。

### 上級: コードを書いて制作する

用意された雛形と開発環境を使い、コードを編集して作品を作ります。練習中は辞書や説明を参照できるようにします。

### 卒業試験: 学んだことを組み合わせる

練習用の補助機能を段階的に減らし、提示された仕様に沿って成果物を作ります。自動採点できる要件はテストで判定し、見た目や使いやすさを評価する場合は評価基準を別に示します。

合格時のメッセージは「おめでとうございます。入門コースを修了しました。これからは実際の制作にも挑戦してみましょう。」を基本とします。文字サイズは画面幅に応じて調整し、読みやすさを保ちます。

## 5. 学習分野とコース

分野、コース、技術を分けて扱います。

| 分類 | 例 |
| --- | --- |
| 分野 | Web制作、ゲーム制作、ロボットソフト |
| コース | Web基礎、Unity 2D、組み込み C |
| 技術 | HTML、CSS、JavaScript、C#、Unity、C |

初期の主な学習経路は「Web制作 > Web基礎 > HTML/CSS/JavaScript」です。各課題には対象段階、説明、必要な部品、達成条件を設定します。

## 6. 画面とナビゲーション

### 画面

- ホーム: サイトの案内と学習分野への入口
- 説明: サイトの目的と学び方
- お問い合わせ: 問い合わせフォーム
- 分野選択: Web制作、ゲーム制作、ロボットソフトの選択
- 分野トップ: 選んだ分野のコース案内
- 初級・中級・上級: 各段階の教材と課題
- 試験: 段階ごとの課題と結果
- エラー・ページ未発見: 状況説明と戻り先を案内

共通ナビゲーションにはホーム、学習分野、説明、お問い合わせへのリンクを置きます。学習履歴や「続きから学ぶ」は、進捗保存機能を実装する段階で追加します。

### 現在の主なルート

実装中の画面遷移は `src/App.jsx` のルート定義を正とします。主な経路は次のとおりです。

- `/`: ホーム
- `/about`: サイトの説明
- `/contact`: お問い合わせ
- `/genre`: 分野選択
- `/genre/site`: Web制作
- `/genre/site/beginner`: Web制作の初級
- `/genre/site/beginner/lesson`: 初級の学習
- `/genre/site/beginner/exam`: 初級試験
- `/genre/site/intermediate/html-css-js`: Web制作の中級
- `/genre/site/intermediate/html-css-js/exam`: 中級試験
- `/genre/site/advanced/html-css-js`: Web制作の上級
- `/genre/site/advanced/html-css-js/exam`: 卒業試験

ゲーム制作とロボットソフトにも分野・初級の画面があります。各分野の教材と試験内容は今後整備します。

## 7. 進捗と試験

試作段階では、合格した段階をブラウザの `localStorage` に保存します。サーバー送信やアカウント間の同期は行いません。合格後に次の段階を解放する条件は、課題単位で定義します。

各試験には最低限、次の項目を設定します。

- 出題数と課題の選び方
- 制限時間
- 合格に必要な点数または達成数
- ヒントの利用可否と得点への影響
- 再受験と途中保存の扱い
- 合格後に解放される教材

「一致率」など採点対象が分かりにくい表現は避け、正解数、要件達成数、自動テスト通過数のように判定方法を明示します。

## 8. アカウントとデータ

アカウント機能では、メールアドレス、パスワード、ニックネームを扱う構想です。認証を導入する際は、パスワード再設定、メール確認、退会時のデータ削除、保存期間を定めます。パスワードを平文で保存してはいけません。

保存機能を追加する場合、扱うデータの候補は次のとおりです。

- ユーザーのプロフィール
- コース、教材、課題、試験の定義
- 課題の進捗
- 試験の受験結果
- お問い合わせ内容

アカウント機能とサーバー側の保存は現時点の実装範囲に含めません。進捗は試作としてブラウザ内に保存し、学習画面と課題の体験を整えます。

## 9. 技術と実装上の方針

### 現在の構成

- React 19 と React Router: 画面とルーティング
- Vite: 開発サーバーとビルド
- CSS: 画面スタイル
- oxlint: 静的解析
- ローカルの JavaScript データ: 課題データの管理

実際の依存関係は `package.json`、画面遷移は `src/App.jsx` を参照します。Monaco Editor、ドラッグ＆ドロップ用ライブラリ、フォーム検証ライブラリ、バックエンドは現時点では導入済みとみなさず、必要になった時点で選定します。

### コード課題の安全性

ユーザーが入力したコードをサーバー上で直接実行しません。ブラウザ内で実行する場合も、実行領域を分離し、実行時間や通信を制限します。サーバー実行が必要になった場合は、隔離された実行環境を別途設計します。

採点は可能な限り画面の見た目だけに依存させず、DOM、イベント、出力値など再現可能な条件で行います。

### アクセシビリティと表示

- スマートフォンでも内容を読めるレイアウトにする。
- 色だけで正誤や状態を伝えない。
- キーボード操作と読み上げに配慮する。
- 見出し、ボタン、フォームには内容が分かる名前を付ける。

## 10. 実装の進め方

1. 現在の画面とルートを整え、分野選択から学習・試験へ移動できるようにする。
2. 初級の教材とパズル課題を整備し、課題ごとの達成条件を定義する。
3. 初級試験、中級教材、中級試験の条件を具体化する。
4. 試作の進捗を `localStorage` に保存し、同じブラウザで再訪したときに状態を表示する。
5. 上級のコード編集と、安全に実行・採点する方式を設計する。
6. 必要性を確認してから、認証、データベース、お問い合わせ運用を追加する。
7. Web基礎の完成後、ゲーム制作やロボットソフトのコースを設計する。

## 11. 今後決めること

- 初級・中級・卒業試験それぞれの問題数、制限時間、合格条件
- ヒントを使った場合の採点方法
- 課題の途中保存と再受験の扱い
- 進捗保存を始める時期と、アカウントを必須にするか
- 対象年齢と未成年者のアカウント方針
- お問い合わせの送信先、返信方法、保存期間
- 卒業試験で自動採点する範囲と成果物を評価する範囲
- 学習履歴や提出コードを保存する期間
- 公開先と、無料枠を超えた場合の費用負担
